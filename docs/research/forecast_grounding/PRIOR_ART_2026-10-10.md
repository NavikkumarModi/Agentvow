## Update: full-text pass over the arXiv HTML versions (same day; `[read-html]`)
Method caveat: the pages were read through a fetch tool that answers questions with a small model, so these are `[read-html]`, not a verbatim human read; quoted numbers should be re-checked against the PDF before they go into a paper.
- **2610.00425** `[read-html]`: confirmed 50 tasks x 4 languages x 3 agents = 600 primary instances plus 400 stochastic trials = 1,000 runs; agents Claude Code, Codex via Copilot, Gemini Code Assist; one generation step plus up to 10 repair cycles; runtime ground truth by ptrace file-access tracing (Sciunit) in containers; stated limits: conditionally imported packages missed, header-only C++ libraries leave no trace. **It does not check completion claims or merged PRs** (test suites only validate prompts). Headline: declared-dependency agreement across agents as low as mean Jaccard 0.073 (JavaScript); manifest macro-F1 against runtime ground truth Python 0.765, Java 0.708, JavaScript 0.219, C++ 0.018; Claude added external packages on 91.8% of standard-library-solvable tasks. The predecessor paper was not located.
- **ResearchEnvBench** `[read-html]`: 44 repositories (created after 2024-01-01); stages C0-C5 (static imports, CPU run, hardware alignment, single-GPU compute, distributed readiness, **hallucination**). **C5 compares the agent's self-reported capabilities (report.json) with hidden probe outcomes**: capability hallucinations Codex 4, Claude Code (GLM-4.7) 17 of 18, Claude Code (Sonnet 4.5) 20, NexAU 14 of 16. Best distributed readiness 37.5%. **No merged PRs.** Venue still not stated on the page. Consequence: "an agent's claim audited against an independent probe" is established; our difference is the claim type (a test result on a real merged PR patch) and the multi-context design, not the idea of auditing self-reports.
- Still unread: the patents, the 2025 predecessor of 2610.00425. SetupBench remains abstract-level.

## Update 2: the remaining reads (same day)
Method as before: `[read-html]` = arXiv HTML read through a fetch tool with a small summarising model; `[snippet]` = search-result summary only; patents read from Google Patents pages (claims paraphrased by the same tool; not a legal reading).
- **SetupBench** `[read-html]`: success = a one-line validation command run in a fresh subprocess after the agent's last action (prints "Setup successful/failed"); **no check of the agent's own completion claim**; no comparison of execution contexts; no merged PRs (dependency-resolution tasks mined from issues). 93 instances = 54 repository setup + 16 dependency resolution + 15 database + 8 background services; overall resolve rates GPT-4o 34.4%, GPT-4.1 50.5%, Claude 3.5 53.8%, Claude 3.7 57.0%, Claude 4 62.4%; repository setup 38.9-57.4%. Relevant to us: an agent omitting the test runner is documented prior art (our B2 "omitted pytest" is the same phenomenon in a different setting).
- **AI-Generated Code Is Not Reproducible (Yet)** (Vangala, Adibifar, Gehani, Malik, arXiv:2512.22387, 2025-12-26, v3 2026-03-23) `[snippet]`: 3 agents (Claude Code, Codex, Gemini), 300 projects from 100 prompts in Python, JavaScript, Java; 68.3% execute out of the box (Python 89.2%, Java 44.0%); 13.5x average expansion from declared to runtime dependencies. Generated projects, not merged PRs. Abstract/search level only.
- **truth (`mcp-truth-check`, Glama listing)** `[snippet]`: deterministic fact-checker for coding agents' claims (`verify_turn`) against the working tree, git diff and *recorded command receipts*; verdicts Supported / Contradicted / Refused. A test-pass claim is verifiable only if a matching command run was recorded after the last code edit. Difference from this project: it checks receipts of runs; Agentvow executes an independent replay. Source: listing page, no repository read.
- **ProofRun** `[snippet]` (one aggregator page, no repository found): a local receipt binding a command's result to the git commit plus a hash of uncommitted changes; STALE when code changes; no LLM, offline; says it does not judge correctness. Same difference as above. Related tools surfaced by the search (`[snippet]`, unread): Trial (a rules-file convention requiring command, exit status and decisive output for each completion claim), BootProof (GitHub Action requiring an observed boot), proofpack (proof-carrying CI gate), ActionProof, korgex.
- **Patents (claims paraphrased from Google Patents; no legal opinion):** **US11379349B2** (IBM, "Verifiable testcase workflow", priority 2020-01-03, listed active): claim 1 stores hashes of a test executable, test environment and test results in a secure database across two computers and raises a tamper alert on mismatch (dependent claims: blockchain, attested secure test computer). **US10698666B2** (Microsoft, "Automatically building software projects", priority 2017-12-29, listed active): claim 1 intercepts a build system's OS call for a missing path and installs a source package containing it (instrumented build). Neither claims replaying an agent's declared recipe against a specific completion claim, but US11379349B2 occupies hashing test environments and results across machines, so the project should not present hash-bound evidence as protectable. **US12204434B2 and CN120780274A were not read** by me.
- **Consequence:** the gap statement stays "potential gap requiring further verification" and is now conditional only on what remains unread (US12204434B2, CN120780274A, the full text of 2512.22387, the tools surfaced under ProofRun, and any prior work the searches did not surface). Receipt/hash systems (ProofRun, truth, Trial, IBM's patent) bind a claim to a *recorded* run; this project's difference is an *independent re-execution* in several contexts with an explicit support basis. That difference is stated, not proven novel.

## Update 3 (2026-10-14): the remaining closest-work reads
Labels as before: `[read-html]` = a page fetched and read through a summarising tool (numbers need a re-check against the primary source before a paper cites them), `[snippet]` = search-result summary only. A pasted summary from the owner listed several of these sources; **I verified each claim below myself and where the paste and the pages differed I followed the pages.**
- **AI-Generated Code Is Not Reproducible (Yet)** (arXiv:2512.22387, v3) `[read-html]`: 300 projects generated by Claude Code (Opus 4.1), OpenAI Codex 0.52.0 and Gemini 2.5 Pro from 100 shared prompts (40 Python, 35 JavaScript, 25 Java); clean-environment execution using only the agent's declared dependencies: 205/300 (68.3%) ran out of the box (Python 89.2%, JavaScript 61.9%, Java 44.0%); three dependency layers (claimed, working, runtime), runtime dependencies from SciUnit / `npm list` / `mvn dependency:tree`; reported 13.5x average runtime expansion, **with per-language multipliers that are inconsistent inside the paper** (equation 17 versus the figure discussion), so that number should not be cited without the PDF. No completion claims, no merged PRs, no comparison of a captured environment against repository setup; no dedicated limitations section found.
- **truth** (`blasrodri/truth`, Rust CLI and MCP server, MIT) `[read-html]`: deterministic checker of agents' claims about code state, diff scope, command receipts and git state; verdicts supported / contradicted / unproven / refused; **a language model only parses the agent's sentence into a structured claim, and a fixed-rule engine decides**; it **does not run the claimed command itself**: "tests pass" is supported only when a recorded matching run (made through `truth run` or captured by Claude Code hooks) exited 0 *after the last working-tree edit*; a green receipt that predates later edits is refused; receipts in a local SQLite file; AST extraction for Rust, TypeScript/JavaScript, Python and Go. Author-reported evaluation (not verified): a labelled precision corpus with zero false contradictions, and a replay of 84 SWE-bench trajectories in which file-operation over-claims were caught in 17%. **Closest existing system to the claim-checking core of Agentvow; it verifies recorded evidence, not an independent re-execution, and has no captured-environment or multi-context comparison.**
- **Trial** (`Da7-Tech/trial`, MIT) `[read-html]`: a rules-file convention, not a tool: every user-visible claim must carry a fresh receipt (exact command, exit status, decisive output); behavioural, enforced only by the agent following the rule (the README says a hook is stronger); judging uses the same model with fresh context. Author benchmark: n = 6 per arm, Haiku 4.5, one fixture; covering test 6/6 vs 4/6, verbatim receipts 6/6 vs 0/6 (hand-scored), correctness 6/6 in both arms. 3 stars, 11 commits. The earlier "unread" Trial is this repository; the similarly named AgentTrial is a different product.
- **ProofRun** `[snippet]`: still only one aggregator page (no repository found): a local receipt binding a command's result to the git commit plus a hash of uncommitted changes, STALE on change, no LLM, offline. Cannot be characterised beyond that.
- **Patents (claims as shown by Google Patents, machine-translated for the Chinese one; not a legal reading; pending status is an assumption).** **US12204434B2** (Karma Automotive; build system supporting code audits and software forensics; priority 2022-08-04; listed active): claims concern a blueprint for a reproducible build, ordered named build steps and a project hierarchy as a single source of truth; **no claim recites replaying tests, capturing a developer or agent environment, verifying a claim about test results or comparing execution environments**. **CN120780274A** (Sichuan Kunmuyang; priority 2025-06-30; pending): a knowledge graph linking requirements, code, tests and deployment; test results update requirement status and freeze branch merges on failure; claim 1 and dependents recite a **cryptographic hash fingerprint of the runtime environment configuration** (kernel version, dependency list, container layers) and a **comparison of the production fingerprint with a test baseline fingerprint, halting deployment on deviation**. It does not recite verifying an agent's claim or replaying tests, but it occupies environment fingerprinting and comparison; Agentvow neither fingerprints for deployment gating nor compares by hash. With US11379349B2 (IBM; hashes of test executable, environment and results) and US10698666B2 (Microsoft; instrumented builds), **the project must not present hash-bound evidence, environment fingerprinting or dependency recovery as its contribution**; a claim-by-claim review by a patent professional is needed before any IP position.
- **Other tools surfaced** `[snippet]`: Proofrail (PyPI; checks an agent's claims against a git commit range and available evidence; verified / contradicted / unsupported / needs review), Tycho (offline local verifier of what an agent did, from git, the filesystem, exit codes and the harness event stream), BootProof (signed attestations; a receipt gate for boot), x-harness (a Go package: an agent writes a completion card, a read-only verifier accepts or withholds), Agent Harness Replay (records and replays coding-agent sessions), Vector Harness (hooks with deterministic checks). **"ReplayPack" and "Agentic Harness", named in the paste, could not be resolved to a unique repository**; they are not characterised here.
- **Consequence for the paper.** The mechanism space (claim extraction, deterministic rules, receipts bound to code state, staleness, hook-based verification) is occupied by several systems, `truth` most closely. What the evidence supports as the remaining candidate gap is **empirical**: a pre-registered measurement, on real agent-authored PR tasks, of whether replaying in an environment captured when the agent ran its tests reproduces more passing results than reconstructing it from the repository, with the contexts compared on one frozen patch and failure modes reported. The paper must say so, must not claim a novel verification mechanism, and must state that the replay evaluates target tests and does not map each natural-language claim to its command.
- **Still not done:** PDF-level checks of every number above; ProofRun's source; Proofrail, Tycho and x-harness repositories; a professional patent review; the full text of 2610.00425's claims about its runtime ground truth beyond the HTML read.

## Update 4 (2026-10-15): source-level verification (PDFs and READMEs read directly)

## Update 5 (2026-10-22): a correction found by the owner and verified in the primary source
**ProofRun (yebiguo/ProofRun) `[read-readme]` and `action.yml`:** besides the local receipt tool described in update 4, the repository ships a composite GitHub Action (`yebiguo/proofrun@v1`) that performs its own checkout of the exact PR head commit (not the synthetic merge preview), clears `.proofrun/` so no checked-in receipt is trusted, and re-runs the checks configured in `.proofrun.yml`. Known limitation stated by its author: the PR can weaken `.proofrun.yml` itself. This corrects earlier statements here, in `VISION_2026-10.md`, in the paper drafts and in `MARKET_AND_MONETIZATION_2026-10.md` that no read tool re-executes the result in a separate clean environment: **independent re-execution of repository-declared checks in a fresh runner exists**. What remains a potential gap requiring further verification is narrower: replaying from the Python package state recorded in the agent's own environment, and comparing that replay with a repository-only reconstruction. Our earlier read of the ProofRun README stopped before its GitHub Action section; the mistake was the incomplete read, not the source.
