# Stage B6 (final registered test of attempt-time capture, unfiltered cohort) — pre-registration, 2026-10-12 (written BEFORE any B6 run)

Owner decision (2026-10-12): fix the misleading error message, then run one final pre-registered test for about $30, **with the sampling protocol changed first**. Done in this commit: (1) when a resource guard (size, disk, timeout) stops an install, Agentvow no longer runs tests in the partial environment and reports "the replay environment could not be built (reason), so no tests were run" with the `AGENTVOW_MAX_ENV_MB` hint (test `GuardAbort`); (2) the cohort is drawn below.

**Why the sampling changes.** B3-B5 drew only from candidates on which reconstruction had already failed, so the contrast "capture vs reconstruction" was between a method and its known failures. B6 draws from **all** structural candidates not used in B1-B5, **without reading any earlier zero-config or screening result**, so the repository-only replay is free to succeed or fail on its own.
**Tasks.** 747 structural candidates (agent-authored AIDev PRs with Python test files) not used in B1-B5; seed 2032; at most 2 per repository; 40 tasks in 31 repositories (`stageb6_select.py`). Target tests = the PR's Python test files. Tasks whose clone or base commit is unavailable stay in the attempted denominator.
**Run.** Same agent (Claude Code, installed default), S0 sandbox, empty virtualenv, prompt C1P, one run per task. **Capture frozen:** the fuller capture of `STAGE_B4_PREREG.md` (pip freeze with `pip` dropped, `setuptools`/`wheel` kept, editable and direct-URL entries dropped, the project's own distribution dropped; replay isolation check as of commit `897c87e`) with the **replay size limit set to 3 GB in the replay subprocess** (`AGENTVOW_MAX_ENV_MB=3072`, inherited by every replay). Contexts, all on the same frozen patch and the same scoped target command: E_repo (zero-config ladder), E_capture, E_recipe_scoped (secondary).
**Validity.** A run is *valid* if the agent's target tests pass in its own environment and fail on the baseline without its changes (checked in the agent's environment).
**Denominators reported (all of them, nothing excluded because capture failed):** A attempted; setup failures; runs; P (agent's tests pass); V (valid); reproduced counts for each context over V, over P and over A (intention to treat); paired counts on V; every capture outcome on V as its own class (pass / fail / inconclusive with its reason: environment too heavy or not built, isolation guard, missing dependency, collection error, import error, other). Script: `analyze_stageb6.py`.
**Primary outcome and rule (on V).** R_c = capture reproduction rate, R_r = repository-only rate, b = runs reproduced by capture only, c = by repository-only only, lead = (b - c)/V.
 - **Supported:** R_c >= 70% AND lead >= 15 points.
 - **No incremental value (stop expanding the capture approach):** R_c <= R_r + 10 points OR lead < 10 points.
 - **Inconclusive:** otherwise. **Underpowered, no reading: fewer than 20 valid runs.**
**Why the lead threshold is 15 points, not B5's 30.** B5's +30 was calibrated for a cohort in which reconstruction had failed by construction. In an unfiltered cohort repository-only replay is expected to succeed on a sizeable share, so a 30-point lead may be unattainable even for a useful capture; the 70% absolute target is kept. This is a judgement made before any B6 data.
**Budget and stopping.** Hard cap $30; a run is not started if spent + $1.5 would exceed it; stop at 40 tasks; an authentication failure stops the run without recording. At about $0.6-0.8 per attempt, 40 tasks may not fit; the budget rule decides.
**Known limits stated in advance.** Capture is pip freeze only (no system packages, services or generated files; the sqlmesh-style generated-file failure is expected to recur); one model; one run per task; reconstruction tasks, not natural bug reports; agents solve a subset and many solved tasks are trivial, so V is a fraction of A; third-party code stays local; the AIDev corpus is dominated by a few agents and repositories.
**What the result would mean.** Supported: invest in an evidence-carrying execution capsule (source state, test invocation, Python environment, configuration, at claim time). No incremental value: stop expanding this capture approach and keep the narrow replay-based verifier.
