# Repair-loop pilot: pre-registration (DRAFT v1, 2026-10-30; NOT FROZEN)

v0 of this document was reviewed adversarially the same day (findings summarised in section 8) and withdrawn: about half the units could not be repaired by construction, the outcome was gameable and mostly circular, and the sample could not support a decision rule. This version is a **pilot with no decision rule**. It can say whether the idea is worth a real experiment, and whether showing findings can do harm. It cannot establish an effect size.

**Question.** When a coding agent is shown Agentvow's findings about a flawed change, does one bounded repair attempt fix the problem without breaking anything, compared with a nudge, CI output, a length-matched placebo and the raw tool output a person would run? **Sandbox only: nothing is merged, pushed, commented on or deployed.** Prior art for the loop (Proof-or-Stop, orthogon agent-verify, FalseGreen; `NOVELTY_BOUNDARY.md`) means no novelty is claimed. Maps to the gate for stage 2 in `docs/strategy/VISION_SUPERVISOR_2026-10-30.md` ("resolution without regressions, compared with CI output alone"); this pilot only decides whether to run that test properly.

## 0. Freeze record (to fill at freeze; any later change to `agentvow/` or `research/repair/` voids it)
To be committed before any run, each by hash: the **eligibility script and the list of eligible pull requests**; the **exact prompt text of every arm**; the turn, time and budget limits; the guard path lists and patterns of section 3; the Agentvow commit, ruff and flake8 versions, Claude Code CLI version and model id; the seeds for arm order and runs (generated by a secure random source, unused until freeze). **A second adversarial review of this version must precede the freeze.** Authorisation to clone and run these open-source repositories and an agent on them in the sandbox: **owner to confirm**.

## 1. Units (three strata, never pooled)
Source: the 43 shadow-pool pull requests with a full audit and arm-5 score at least 2 (36 repositories). Before environment and head-commit filters (to be applied by the committed script and listed with reasons):
- **R, repairable (primary): 12** with a CONTRADICTED finding (10 lint_clean, 2 no_downstream_impact). Of these, the primary stratum is the subset whose first-pass label is **positive** (the finding was a true flaw), expected 4 to 8; the exact set is fixed by the script.
- **F, false alarm: 16** first-pass negative plus any R unit labelled negative: the finding was wrong. Outcome here is harm (section 3).
- **I, impact-attention, descriptive only: 31** whose only flag is an attention on an UNKNOWN impact claim. No code change makes this flag go away; the only exits are editing the description or changing the audit. No outcome claim; reported as counts of what the agent did.
- 13 units were never labelled and 4 are unscorable; they are listed, not analysed in R or F. Labels are LLM labels (class kappa 0.66; 3 of 12 first-pass positives overturned in the second pass); where a second-pass label exists, a unit is positive only if both passes agree.
The sample is small by necessity. **Minimum detectable effect** for a paired binary comparison at n of about 6 to 8 is a near-total difference (for example 8 resolved against 1); at n of 35 it is about 35 to 45 points. No test is a gate; intervals are exact (Clopper-Pearson, exact McNemar) and descriptive.

## 2. Arms (every unit gets every arm, from a fresh checkout of the head commit, in seeded random order, serially)
- **A nudge.** The description plus "review your change for mistakes and fix them". No findings.
- **B CI output.** A plus the head commit's CI result (failing checks and logs, or "CI reported no failures"). For most units this is nearly empty (CI was none for 25 of the 43, success for 11, failing or pending for 7), so **B is close to A plus a reassurance and is not called a fair CI control**.
- **C Agentvow findings.** A plus the findings of the Agentvow record in plain language, as a person would read them.
- **D placebo.** A plus a plausible but non-diagnostic finding list of the same length and format (findings from another pull request, shuffled). Separates specific true information from extra text and a pointed task.
- **E raw tool output.** A plus the plain output of the lint or test command the project itself would run (for lint findings this is the real competitor; Agentvow's contribution over it is probably nil).
**Three independent runs per cell** (seeded). Primary summary per unit and arm: runs resolved out of 3. The description is **frozen**: the agent may not change it, and re-audit always uses the original text.

## 3. Outcomes (deterministic; no LLM in the verdict path)
A **clean resolution** on a run requires, on the final state, all of:
1. The target finding is gone when Agentvow and, **independently**, the project's own pinned lint or test command (clean base, project config) are re-run. A finding that flips between two identical audits is non-deterministic and the unit is excluded.
2. No new CONTRADICTED finding.
3. **Guards:** the final diff touches no lint, test or CI configuration (`pyproject.toml`, `setup.cfg`, `tox.ini`, `.flake8`, `.ruff.toml`, `conftest.py`, `.pre-commit-config.yaml`, CI files; list fixed at freeze); adds no `noqa`, `pylint: disable`, `type: ignore`, `ruff:`, `pragma`, `skip` or `xfail` text (pre-existing ones counted separately); the set of test ids collected at the final state contains the set at head and every test that passed at head (passing in two consecutive runs at head) still passes; the change list never shrinks (no reverting of hunks of the head change beyond a line cap); the diff is under a line cap. Units with no interpretable passing test set are marked **regression guard unavailable** and their resolutions reported separately, never as clean.
4. Environment unreconstructable after the change is counted as "turned into UNKNOWN", not resolution.
**Harm outcome (stratum F):** the agent changed code in response to a false finding, or introduced a regression. This is the safety result a supervisor must show: arm C could be worse than A here.
Budget-truncated or timed-out runs score as failures, not as dropped.

## 4. Analysis (descriptive)
Per stratum and arm: runs resolved per unit, units with at least 2 of 3 resolved, exact intervals, a table of discordant units for C against each of A, B, D, E, and per-unit run variance. Stratify R by finding kind. No pooling of strata. "Inconclusive" is a named outcome and the expected one for most comparisons.

## 5. What a result may be used for
There is **no decision rule**. Outcomes and their consequences: (a) C no better than D or E on R, or C harmful on F: do not build the repair loop as a claim; record in `NOVELTY_BOUNDARY.md`; (b) C clearly better than D and E on R, directionally consistent across units, and not harmful on F: justifies pre-registering a properly powered experiment on a larger, labelled sample; (c) anything else: no claim. Nothing here supports an acting consumer or an autopilot.

## 6. Sandbox (stated as built, not as wished)
The existing precedent `research/preconditions/sandboxed_claude.py` runs Claude Code under `sandbox-exec` with `(allow default)`: writes confined to the task directory, venv, scratch and Claude's state; credential directories read-denied; **network allowed** (the model API and the package index are needed and `sandbox-exec` cannot filter by host); **residual: the agent's child processes can reach Claude's own credentials and make arbitrary outbound requests**. Read access to the Agentvow `data/`, `docs/` and `research/` directories (labels, prior results) is denied to the agent. There is no network-write monitor in this sandbox, so no stopping rule depends on one. A proxy-mediated, no-network-after-install variant is a build task that is not done.

## 7. Resources
Disk: 4.9 GB free (98% used) on the host, so runs are strictly serial, each checkout and venv is deleted after use, and the pilot aborts below 2 GB free. Cost: about 8 units x 5 arms x 3 runs for R (120 sessions) plus about 16 x 5 x 3 for F (240) plus I observation-only runs if budgeted, at about 1 USD per session as a rough planning figure (the existing script caps a session at 0.5 USD); pre-register a per-session cap and a total cap before freeze. The R-only pilot (about 120 sessions) is the minimum meaningful run. A human spot-check of clean resolutions is **not planned** unless a named reader and a rubric are added.

## 8. Findings of the v0 review that shaped this version
Eligibility was 43, not "about 35"; 31 of 43 are UNKNOWN impact flags no code change clears; 16 of 43 were first-pass negative, so "true-positive-ish" was wrong; power at n of 35 is about 30 to 40% for +20 points and hopeless at 6 to 12; the draft outcome was gameable (description edit, config or noqa changes, reverted hunks, skipped tests) and circular (same checks re-score), hence the frozen description, guards and independent re-run; B was nearly empty (placebo D and raw-tool arm E added); one run per cell cannot show variance (three runs); the sandbox claim "package index only" was false as written; no disk floor or cost cap; freeze mechanics were incomplete.

## 9. Known threats
Historical pull requests written by other agents, repaired without task context; LLM labels define the strata; one agent and one model; lint-dominated repairable set (one finding kind); the agent can read its own checkout history; results do not transfer to live workflows. All stated before any run.
