# Pilot protocol (pre-registered before any participant, 2026-10-13)

**Purpose.** Learn whether developers who already use coding agents find Agentvow's output (verdict classes with plain-language reasons, UNKNOWN, changed-line coverage, capture-based replay) understandable and worth acting on, and where it gets in the way. It is a usability and feasibility pilot, **not a study of effectiveness**: no inference, no rates reported as results.
**Who.** 5-10 developers who use an agent (Claude Code, GitHub Copilot, or similar) on a Python project with pytest tests, on macOS or Linux, for about two weeks. Self-selected volunteers; no compensation implied; participants may stop at any time.
**What they do.** Install the tool from a pinned commit (`docs/pilot/QUICKSTART.md`), turn on the opt-in hook (`--background-tests --capture --changed-coverage`, all opt-in; the quickstart lists exactly what to enable), work as usual, and keep a short diary (`docs/pilot/FEEDBACK.md`) for the turns where Agentvow said something. They send the diary and the end survey if and when they choose.
**Privacy (the rule of the pilot).** Nothing is collected automatically; Agentvow sends nothing anywhere. We ask for **no source code, no repository names, no transcripts**. Participants describe what Agentvow said in their own words or paste only the report text they are comfortable sharing. Capsules contain package pins and the Python version only (never environment values), and stay on the participant's machine.
**What we ask about (all self-reported).** (1) Did the output make sense without help? (2) For each UNKNOWN, coverage note or CONTRADICTED: did you act on it, and was it right? (3) False alarms and missed problems you noticed. (4) Did the hook ever slow, break or confuse the agent session? (5) Would you keep it on?
**Success criteria, written in advance (qualitative; N is too small for anything else).** The pilot supports going further if: at least about half of participants report acting on at least one UNKNOWN or coverage item; fewer than about one reported false alarm per participant per week; no participant reports the hook breaking or timing out an agent session without an easy fix; and about half would keep it on. Each unmet criterion becomes a concrete fix, not a conclusion about the idea.
**Stopping rules.** Any report of data leaving a machine, of the hook modifying the participant's repository outside `.agentvow/`, or of a wrong all-clear that mattered: stop the pilot, investigate, fix, and tell the participants.
**What we do with it.** Fix defects, rewrite unclear wording, decide whether capture and coverage should become defaults, and decide whether the larger routing study is worth running. Quotes are used only with permission.
**Known limits.** Self-selected users, self-reported outcomes, a Python-only tool, hooks are a Preview feature in some agents, results from different agents are not comparable.
