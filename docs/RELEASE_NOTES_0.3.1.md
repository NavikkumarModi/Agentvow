# Agentvow 0.3.1

Agentvow checks what a coding agent says it did against what it can independently observe. It informs you; it never approves, rejects or merges, and no language model decides a verdict. Still a prototype, not a safety verdict.

## New
- **GitHub Action: opt-in `run-tests`.** With `run-tests: "true"` (default `false`; `test-timeout` defaults to 900 seconds) the action also replays the repository's tests in the sandbox on the runner (bubblewrap is installed on Linux), in an environment built from the repository's own files, measures changed-line coverage and adds the evidence pack to the job summary and the pull request comment. **This runs the pull request's code** (installs sandboxed with network, tests sandboxed without; no tokens are passed in) and the pull request writes the test output, so the pack is evidence to weigh, not verification. The action refuses `run-tests` on `pull_request_target`, `workflow_run` and comment events, and for fork pull requests on self-hosted runners; the timeout must be a whole number. Run once on GitHub, on a same-repository pull request on `ubuntu-latest` (360 tests passed in the replay); not verified on forks or macOS runners.
- **`check --evidence-pack` builds its environment from the repository's own files** (setup and requirements files, the CI workflow's install steps, Dockerfiles) also when run by hand without a capture, as the hook path already did. Before, this path used only the zero-config ladder, so a dependency installed only by the CI workflow was reported as a missing dependency.
- **Sandbox escape closed.** Probes of interpreters in repository-controlled environments (`import pytest`, `import coverage`, direct-URL listing) now run inside the sandbox from an empty directory with a minimal environment. An adversarial review showed that a planted `coverage.py` in the checkout or a `.pth` file written by a package install would otherwise have run unsandboxed with the runner's environment.
- The environment build has an overall wall-clock budget (`AGENTVOW_BUILD_BUDGET`, default 900 s).
- The pack's markdown report (the pull request comment) now lists the install steps and CI environment values the replay used, notes steps that failed or were left out, and names the files it read that the change touched.

## Known limits
Python repositories only; capture covers Python packages, not system packages, services, generated files or secrets; running tests needs macOS or Linux; `agentvow init` supports Claude Code only; the hook shapes are verified for Claude Code 2.1.263 and (earlier) Copilot in VS Code only; the workflow reader supports a YAML subset; the results behind the product claims are feasibility-scale and reproduction is not correctness. See `docs/SECURITY_MODEL.md` before using `run-tests` on pull requests from people you do not trust.
