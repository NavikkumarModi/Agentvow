# Evidence pack

`agentvow check --run-tests --evidence-pack` (it turns on the test run and changed-line coverage for you) adds one section to the report with **three separate dimensions of evidence plus a record of what the replay did not recreate**. They are never combined into a score or a badge, and the pack changes no verdict.

1. **Execution receipt.** What ran (the test command), on which exact state (commit, plus uncommitted changes if any), compared with which base, and that the receipt is valid only for that state: any later edit makes it stale.
2. **Reproducibility.** The same tests are run in up to two clean sandboxes: one built from the packages **captured when the agent ran its tests** (needs `agentvow capture`, see `docs/CAPSULES.md`) and one built **from the project's own files** (since 0.3.0, `agentvow/baseline.py`: the project's setup files and requirements files, the `pip install` lines of the first CI workflow job that runs the tests, `pip install` lines in Dockerfiles and the other requirements files, each validated like a recipe; the pack lists the steps it used; anything it does not understand is left out, never guessed; it needs no extra dependency). The pack states whether the result reproduces in both, in one only, or in neither, and when the two disagree it says what was observed, for example "reproduces from the captured packages but NOT from the project's own setup (missing dependency: six): someone who clones the repository may not be able to reproduce it". Without a capsule only the project-native context runs and the pack says the captured replay is missing. When a context did not reproduce, the pack adds a plain-language **next step** for it (`agentvow/advice.py`): which package the context lacked (and, with two contexts, that the other reproduced), a credential the tests need that no replay supplies, an install stopped by the size, disk or time guard (with the setting to change), a command that ran no tests, a test timeout, or a real test failure (a result, not a gap). Text only, built from what the replay recorded; it never guesses about the code.
3. **Changed-line coverage.** How many changed executable source lines the tests ran, with the lines and files that no test reached (and the first line's text), and files the tests never loaded. "Ran" is not "was checked": line coverage can show a line was not executed; it cannot show a line was asserted.

**In the agent hook:** `agentvow check --hook --evidence-pack` (the flag implies the background test run and the environment capture). The hook answers at once with what it can see, then a detached run captures the agent's packages, replays in both contexts, measures changed-line coverage and replaces the result with one that includes the pack. Without a project environment to capture, the pack shows only the project-native context and says the captured replay is missing. The hook never blocks the agent.

```bash
agentvow capture --repo .                                   # right after the agent's tests
agentvow check --repo . --transcript msg.txt --evidence-pack --html report.html
```

4. **Not reproduced by this replay (a record, not evidence and not a judgement).** Where the repository's tests and changed code *reference* things a replay does not recreate, by name only: environment variables read (names, never values; "required" when read with `os.environ["X"]`), external programs the tests invoke (`subprocess`, `shutil.which`), network use (network libraries and non-local URLs: the replay has no network), service and environment files present (`docker-compose.yml`, `Dockerfile`, `.env.example`), git-ignored files that exist on this machine but not in a fresh clone (generated fixtures, local data, caches), and a Python or operating-system difference between capture and replay. Static analysis only: nothing is executed, a reference is not proof a test needs the item, and an empty list is not proof that nothing is missing. It never changes a verdict.

**What it does not do:** it does not run a second claim check (the verdict comes from the primary replay as before), does not cover system packages, services, generated files or secrets, and a pass in both contexts is not a correct change. It informs a person; it never approves, rejects or merges. A failure while building the pack is reported in the scope line and never hides or changes the verdict.
**Cost:** two environment builds and two test runs instead of one.
