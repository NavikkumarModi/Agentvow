# Market gap and where to invest (2026-10-22): a proposal for the owner

Status: a proposal, not a plan. **Source status: every market fact below is `[snippet]`** (seen only in a web-search result summary, mostly secondary blogs and vendor surveys); none was checked against the original report or pricing page. Do not quote these numbers publicly before doing that. Statements about gaps are "potential gap requiring further verification". Our own evidence is in `docs/strategy/PRODUCT_EXPLORATION_2026-10.md` and the studies it cites (feasibility scale; reproduction is not correctness).

## 1. What the market looks like `[snippet]`
- **LLM code reviewers read the diff and comment.** CodeRabbit (about $88M raised, $24 to $48 per user per month, reported), Greptile ($30 per seat including 50 reviews, then $1 per extra review, reported), Qodo (about $120M raised, $30 per user per month for teams, sources disagree), Cursor Bugbot (reported 2M+ PRs reviewed per month), Graphite (stacked PRs, merge queue, an agent). A 2026 roundup says AI review became a required gate because agents open more PRs than humans can read. These are well funded and crowded; this is not where to compete.
- **Governance and provenance is the next layer.** Vendor guides argue for a merge gate for agent changes plus session-level provenance (prompt, tool actions, files touched); GitHub shipped commit-to-session tracing in March 2026; a GitLab 2026 report (secondary summary) says 92% of organisations report AI-code governance challenges and 34% could actually trace an incident to AI code. Auditors reportedly already ask about AI tool inventories and review procedures for AI output (frameworks named: NIST AI RMF and SSDF, EU AI Act provenance, SOC 2, ISO 27001).
- **The review bottleneck is real, per vendor-run surveys.** Sonar's survey (1,100+ developers): 96% do not fully trust AI code to be correct, 48% always check it before committing, 38% say reviewing it takes more effort. GitLab (Harris Poll, 1,528 people): 85% say the bottleneck moved from writing to reviewing. Both come from companies that sell verification.
- **Agents' PRs are gated for a reason that matters to us.** GitHub's docs: workflows do not run automatically on Copilot-pushed changes; a human clicks "Approve and run workflows" because workflows can be privileged and reach secrets. In March 2026 GitHub added an admin setting to skip that approval, and extended similar gating to PRs from `github-actions[bot]` in June 2026.
- **Volume is concentrated in local agents.** One index (secondary) says Claude Code, Cursor and Replit Agent account for 91% of attributed agent commits and PRs on public GitHub; autonomous-agent PRs are under 5% of PRs even at elite organisations (LinearB, secondary). Merge-rate figures conflict by methodology (32.7% to 79% for agent PRs).
- **Monetisation benchmarks.** Per-seat tiers of $15 to $50 per developer per month; usage add-ons (about $1 per review); open-core precedent (Semgrep: free community tier, about $35 per contributor per month for teams, custom enterprise; third-party blog).

## 2. The potential gap
Reviewers tell you what *looks* wrong; provenance tools record what the agent *did*. As far as these sources and our README reads of `truth`, ProofRun, Proofrail and Trial show, nothing sits in between and **re-executes the agent's "tests pass" in a separate, clean, secret-free environment and reports reproduced / not reproduced / unknown, with what could not be checked** (the part Agentvow has). Our studies support a narrow version of it: the agent's recorded packages reproduced 91% of valid passing results (feasibility scale, one model, Python), repository files alone reproduced less, and the cross-day and Linux checks held. Two things make it more than a feature: (a) a deterministic, non-LLM verdict is something an auditor or a policy can point at, which an LLM reviewer's comment is not; (b) the GitHub approval gate means a *safe* pre-CI replay (no secrets, network off for tests) has a natural moment of use for agent PRs. **Unverified:** that anyone will pay for it, and whether GitHub or a reviewer vendor ships the same thing (the first falsifier in the vision note).

## 4. Proposal: evidence-gated merges for agent changes, open core, in three gated stages
**Stage 0, now, free and open (MIT):** the CLI, hooks, Action and receipt format stay free. Purpose: adoption and credibility; nothing here needs users to be recruited. Add the option-4 MCP pre-flight only if an MCP-capable agent can be installed and live-tested.
**Stage 1, one experiment (a few dollars of agent runs, plan and stop rule written first):** does an agent, told by an instruction file to run `agentvow capture` and attach the result, produce a capture that replays as often as the harness-made ones? Gate: if a replay from agent-made captures reproduces at least as often as zero-config reconstruction by a clear margin, option 1 has its key ingredient; if not, cloud-agent PRs get only the repository-files context and option 1 is a weaker product.
**Stage 2, the first paid thing, only if stage 1 passes or a design partner appears:** the **policy and audit layer** (option 5 in its smallest form): a GitHub App that does not execute code itself at first, but (i) reads the receipts the Action or hook already produced, (ii) enforces a merge check ("reproduced, or UNKNOWN explicitly acknowledged by a named human, with scope stated"), (iii) keeps an exportable audit record per agent PR (what ran, on which exact state, which contexts reproduced, what was not reproduced). Hosted replay of untrusted code is deferred; it is where the cost and risk are.
**Pricing hypotheses to test, not decide (anchored to the benchmarks above):** free for public repositories and individuals; a team tier priced per active contributor in the $15 to $35 band that reviewers and Semgrep use, or per gated agent PR (about $0.50 to $1, mirroring Greptile's usage add-on) because the unit of value is an agent PR, not a developer; an enterprise tier for audit export, retention and SSO. Which of seat and per-PR works is a question for the first design partner, not for a spreadsheet.

## 5. What would stop or change this
No design partner or inbound interest after the open tier is public; GitHub or a reviewer vendor shipping independent replay with captured environments; stage 1 showing agent-made captures replay poorly; a buyer saying a deterministic receipt is worth less than an LLM reviewer's comment. The honest unknown under all of it is demand: we have no users and the pilot was dropped, so stage 0 is also the cheapest way to find out whether anyone cares.

## 6. Decisions only the owner can make
Whether monetisation is a goal at all, or reputation and research; whether a hosted component and its security burden are acceptable; whether to spend on the stage 1 experiment; whether to look for one design partner (a single team using agents on PRs) as the only validation that matters; and whether to verify the market numbers above against primary sources before anything is said publicly.
