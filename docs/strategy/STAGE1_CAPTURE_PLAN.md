# Stage 1: can an agent produce independently usable execution evidence? (plan and stop rules; written 2026-10-22, before any agent run or engineering)

Registered when committed; any later change is a deviation and goes in the log at the end. Owner decisions that shape it (2026-10-22): monetisation is an option, not the primary objective; Agentvow stays open source and adoption, repeated pain and trust in verdicts come first; a hosted component is acceptable but **no hosted code execution yet** (execution stays local or on a customer-controlled runner); the Stage-1 experiment is approved with a hard budget and predefined stop rules; design-partner search starts now. Market facts behind this are snippets (`MARKET_AND_MONETIZATION_2026-10.md`), corrected on 2026-10-22: independent re-execution of repository-declared checks exists (ProofRun's GitHub Action), so the proposition under test is the narrower one, **replay from the Python package state recorded in the agent's own environment, compared with a repository-only reconstruction**.

## 1. Two questions, two gates (a pass on the first does not establish the second)
- **Gate A, agent behaviour:** will an instructed agent run capture at the right point and produce a valid artifact?
- **Gate B, architecture:** can that artifact reach a *separate* verifier and give trustworthy evidence there?
The current capsule is signed with an HMAC key in the user's local Agentvow home (`agentvow/reality.py`); a separate verifier cannot validate it, and **the key must never be shared with a service as a shortcut**. Gate B therefore needs a different trust design, built and tested first because it costs nothing.

## 2. The trust design to be tested in Gate B (engineering, before any agent spend)
A portable, unsigned **capture bundle** (`agentvow capture --export FILE`): schema, the agent's Python version and platform, the plain pinned packages (as today), the test command, and a **content binding**: the git tree object hash that the working tree would have if committed as it is (computed with a temporary index, so it equals `git rev-parse <commit>^{tree}` of the commit the agent later makes if nothing changed). No environment values, no paths. A verifier mode (`agentvow check --from-capture FILE`, no key needed) that (1) recomputes the tree hash of its own checkout of the pull-request head and **refuses to replay** if it differs ("this capture was made for a different state"); (2) replays from the listed pins in its own clean sandbox; (3) reports the result with the basis **"agent-supplied capture, not authenticated: made for this exact state, replayed here"**. Why signatures matter less across machines: the verifier's own replay is the evidence; a false bundle can only make the verifier replay other packages (sandboxed, plain pins only, same exposure class as any recipe), and the stated basis says so. Reproducibility is not correctness, as before.

## 3. Gate B0, no agent cost (run first)
Build the export and the verifier mode with unit tests, then test on (a) the existing B6 captures (16 re-runnable valid runs, recorded packages, rebuilt states), (b) injected negatives: a file edited after capture, a different commit, a bundle for another repository, a bundle with a changed Python minor version (must be flagged), an environment secret exported in the shell during capture (must not appear in the bundle; scanned). **Pass:** all injected stale or mismatched bundles refused without replay (100%, at least 8 injected cases across the four kinds); no bundle contains an environment value; on the B6 captures the verifier's result equals the in-process replay result in at least 14 of 16; no "supported" verdict whenever the binding fails or the replay did not run. **Fail:** any accepted mismatch; one repair and a rerun are allowed, a second failure stops the cloud-agent route.

## 4. Gate A, the agent test (budget-capped)
**Tasks:** 12 small Python repositories written by me and committed to the repository **before** any run, each with a hidden oracle written down in advance: 6 controls (every dependency declared in a requirements file) and 6 hidden-state cases (3 with a package the task needs that no repository file declares, 2 where a package version matters and the file leaves it unpinned, 1 where a pytest plugin is needed but undeclared). For each, the repository-only reconstruction (the product's project-native context) is run on the reference solution before the agents run and its outcome recorded, so "value beyond repository-only" is not decided afterwards.
**Agent flow:** Claude Code headless (`claude -p`, the installed default model, one run per task, fresh empty environment, nothing preinstalled), a project instruction file written by `agentvow agent-instructions` plus one added instruction to run `agentvow capture --export` after the final test run; **no hooks installed**, because the test is whether an instruction alone works. Hard cap per run $0.75 and **total $9** (expected $3 to $5); stop on authentication errors, as in the earlier studies. Implementation time and replay cost are recorded separately.
**Measured per run:** (1) did the agent invoke capture, and after its last test run; (2) is the bundle valid and bound to the final state (tree hash equals the final commit's); (3) does the external verifier (Gate B mode, fresh checkout, no key) accept it and replay it in a clean environment without manual repair; (4) does the replay reproduce the agent's passing test result; (5) on hidden-state cases, did capture reproduce where the repository-only reconstruction did not; (6) bundle scanned for secrets; (7) any "supported" verdict when the replay failed or evidence was unavailable.
**Security conditions (any violation fails the stage):** no secret in any artifact; no stale or mismatched bundle accepted; no misleading supported verdict.

## 5. Decision rules (fixed now)
| Decision | Rule |
|---|---|
| Proceed with the local capture workflow | at least 10 of 12 runs produce a valid, correctly bound bundle; at least 9 of 12 give the expected independent replay result; no false-supported verdict; no secret leakage |
| Proceed with cloud-agent feasibility work | the line above passes AND Gate B0 passed AND, on the 6 hidden-state cases, capture reproduced where repository-only did not in at least 3 (**an addition to the owner's table: without it the product's reason to exist is untested**) |
| Pause and repair | capture is reliable but failures come from a clearly identified implementation limit (unsupported interpreter, snapshot-binding bug); one repair and one fresh evaluation set of 12 new tasks (further cap $9) |
| Stop the cloud-agent route for now | the trust or transfer boundary stays unresolved, stale evidence can be accepted, or the second evaluation after repair still misses the thresholds |
Twelve runs support a low-cost go/no-go on this prototype, not a general claim about coding agents or evidence of market fit. "The capture replay succeeded" and "the repository reproduces from its own declarations" remain different statements and are reported separately. Hard total budget for both rounds: $18.

## 8. Gate B0 results (2026-10-22; script `research/preconditions/b0_bundle_check.py`; output `data/preconditions/stageb6_b0_2026-10-22.jsonl`; unit tests `tests/test_bundle.py`)
**Population.** The 20 valid B6 runs whose capture passed on macOS: 16 re-runnable, 4 not (untracked files not in the saved patch).
**(1) Key-less verifier against the registered capture result.** A portable bundle was made from each run's recorded packages and bound to the content hash of the rebuilt state; `check --from-capture` (no key, fresh checkout, scoped target command) replayed it. **15 of 16 pass** (registered threshold: at least 14 of 16): met. The one that does not, onefilellm#71, is explained by the design, not by a binding fault: the agent's recipe declared `RUN_INTEGRATION_TESTS=false`, the registered capture replay applied it, and the bundle carries **no environment values on purpose**, so the verifier ran the integration tests, which fail without network and credentials. This is the cost of the no-secrets rule: non-secret test switches are lost. Possible later feature, not built: an allowlist of explicitly named, non-secret settings carried in the bundle.
**(2) Injected stale or foreign bundles, refused at the binding step before any replay.** On the 16 states: a tracked file edited after capture **16 of 16** refused; an untracked file added after capture **16 of 16**; a bundle made for another run (foreign repository) **15 of 15** (the first run has no foreign bundle); the restored state accepts its own bundle again 16 of 16. In the unit tests: a different commit, a bundle for another repository, a late untracked file and a late edit are refused (8 tests, `tests/test_bundle.py`). **47 injected cases in the replay data plus the unit cases, all refused; the threshold (at least 8 across four kinds, 100%) is met.** A mismatched bundle at the command level never produced a supported verdict (end-to-end unit test).
**(3) No environment value in any bundle.** A planted secret was present in the exporting and verifying process: **0 of 16 bundles and 0 of 16 findings** contain it; the unit test plants a token the same way. **13 of 16 findings say the capture is not authenticated** (the other 3 were UNKNOWN verdicts whose text does not go through the capture-basis sentence: the verdict is not "supported" so the sentence is not appended; the receipt and policy carry `capture_authenticated`).
**Reading: Gate B0 passes.** What it does not show: that the same holds for bundles made by an instructed agent (Gate A, deferred), for other operating systems, or against a malicious bundle writer beyond the binding and plain-pin rules (see `docs/CONTROLPLANE_THREAT_MODEL.md`).
